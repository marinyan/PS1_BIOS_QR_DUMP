# PS1 BIOS Color Video Dumper

初代PlayStation実機の映像出力をデータ転送路として使い、ユーザー自身が所有する本体の
512 KiB BIOSをPCへ取り込むための実験的なツールです。

はむ氏による音声を利用したPS1 BIOS転送から採用したのは「本体のAV出力からBIOSを運ぶ」
という考え方です。そこから映像なら高速化できるのではないかと着想し、コード、プロトコル、
画面形式を独自実装しています。既存ダンパーへのコード上の依存はありません。

## ディレクトリ

- [`dumper/`](dumper/) — PS1で動く送信側。SDKを使わないベアメタル実装
- [`receiver/`](receiver/) — 録画した動画を解析するPC側。ブラウザだけで動作

## 転送方式

- 320×240画面を40×30個のセルに分割
- 8色を使い、1セルへ3ビットを格納
- 1画面あたり318バイト
- 起動時に4 KiB窓のLZSSで圧縮し、小さくならない場合はRAWへ自動フォールバック
- 転送ID、通番、総数、全体CRC32、フレームCRC32を付加
- 40×30の4bppテクスチャ（600バイト）だけをPIO転送し、GPUで320×240へ拡大
- 3 VSyncの明示保持と全コードの無限周回で、30fps撮影の読み落としを回収
- 3個の白黒マーカーをフレームごとに追跡し、通常の手持ち撮影による移動・回転・拡縮を補正

PCSX-ReARMed上では15コード/秒、圧縮ストリーム換算で約4.66 KiB/sです。検証に使った
`psxonpsp660.bin` は524,288バイトから298,714バイトへ縮み、1,649画面から940画面に
減りました。起動時の圧縮処理を含め、録画開始から約63秒で1周目を復元しています。
30fps・960×720・H.264約1.7Mbpsへ再圧縮した録画でも約65.7秒で524,288バイトが揃い、
全体CRC32と元BIOSのバイト列が一致しました。圧縮率はBIOSの版によって変わります。

## 含めないもの

- Sony製BIOSの内容
- SonyのCDライセンスセクター
- 既存BIOSダンパーのコード
- 外部ライブラリのコピー

## 撮影形式

ブラウザ互換性を優先し、H.264/AVC・720p以上・30fps以上を推奨します。30fpsでは
取り逃しを次周で回収できるよう、3分程度録画してください。HEVC/H.265もブラウザが
再生できる環境では利用できます。

PCSX-ReARMedの実録画を960×720・30fpsへ変換した試験では、H.264約1.7Mbpsと
HEVC約0.8Mbpsの双方で512 KiB全体を復元し、CRC32が一致しました。極端な低解像度・
低ビットレート圧縮は色セルを破壊するため非対応です。

NTSC RCAについては、RGB→YIQ→3.579545 MHz副搬送波への変調→復調を行う波形モデルも
自動テストに含めています。RAW経路の回帰試験では、長いケーブルと安価なUSBキャプチャを
想定した最悪条件でも、512 KiB・1,649チャンク全体を棄却なしで復元し、CRC32が一致しました。
限界は [`receiver/README.md`](receiver/README.md) に記載しています。

## 参考にした先行例

本プロジェクトの直接の着想源は、はむ氏の
[「特別な機器に頼らず初代プレステのBIOSを吸い出す！」](https://i486.mods.jp/ichild/ps1bios)
です。音声としてBIOSを運ぶ実装を見て、同じAV出力を映像データへ使えば高速化できるのでは
ないかと考えたことから開発を始めました。

TINY野郎氏の
[「新・PC-6001シリーズのBIOSデータをデータレコーダーもフロッピーも使わずにPCに移す」](https://tiny-yarou.com/b2mvp6col.html)
では、8色の各ドットへ3ビットを載せ、動画からROMを復元する方式が実用化されています。
本プロジェクトはその公開された考え方を参考にしつつ、PS1向けの画面形式とプロトコルを
独自に設計しています。

GOROman氏の
[「PS1 BIOS Video Ripper ZX」](https://goroman.github.io/ps1-bios-ripper-zx/)と
[技術解説](https://gist.github.com/GOROman/050176a1e53c90850a4e5c0ad6306d01)からは、
転送前圧縮とRAWフォールバックを仕様情報として参照しました。コードや画面形式は流用せず、
スマートフォンでの光学撮影を優先する40×30・8×8セルの既存方式へ独自に実装しています。

通信仕様は [`PROTOCOL.md`](PROTOCOL.md) にまとめています。

## 現在の状態

通信プロトコルとブラウザ受信側は自動テスト済みです。PS1送信側は
`mipsel-none-elf-gcc 12.3.0` によるMIPS-Iクロスビルドまで確認していますが、実機表示は
まだ未検証です。RetroArchのPCSX-ReARMedでは、生成したPS-X EXEをヘッドレス実行して
録画し、LZSS圧縮した940チャンクから524,288バイトを復元して全体CRC32が一致する
ところまで確認しています。320×240×16bppのフレーム全体を毎回PIO転送する方式から、
600バイトの4bppテクスチャを転送してGPUで拡大し、さらに転送前圧縮を加えることで、
復元時間を2分19秒から約63秒へ短縮しました。`mkpsxiso`を使う任意ターゲットで
ライセンスセクターを含まないBIN/CUEも生成でき、PCSX-ReARMedでCUE起動と画面データの
照合まで確認済みです。無改造PS1のCD認証を通るイメージではないため、実機ではmodchip、
swap方式、または既存のhomebrewランチャーなどが別途必要です。
