# Receiver

録画したPS1画面からBIOSを復元する受信側です。外部ライブラリやサーバーは使わず、
ブラウザの動画・Canvas APIだけでローカル処理します。

## 使い方

1. `index.html` をChromeまたはEdgeで開きます。
2. 撮影した動画を選びます。
3. コード画面までシークします。
4. 「四隅を指定」を押し、左上→右上→右下→左下の順にクリックします。
5. 「解析開始」を押します。
6. 全チャンクが揃ったら生成されるリンクから `bios.bin` を保存します。

動画は外部へアップロードされません。ページ内ですべて処理します。

カメラは固定し、露出・ホワイトバランス・フォーカスをロックしてください。直接映像を
キャプチャできる場合は、その方が安定します。

撮影はコード部分が720p以上になる構図を推奨します。互換性を優先する場合は
H.264/AVC・30fps以上を使い、30fpsでは取り逃しを次周で回収できるよう5分程度録画して
ください。60fpsならさらに安定します。HEVC/H.265もブラウザが再生できれば解析できますが、
OSやブラウザによってはデコーダーがありません。

実録画から次の再圧縮条件を作り、ブラウザ受信側で全体CRC32まで検証しています。

- H.264 High、960×720、30fps、約1.7Mbps、2周
- HEVC Main、960×720、30fps、約0.8Mbps、2周

4bppテクスチャ描画へ高速化した送信側についても、PCSX-ReARMed録画を
H.264・960×720・30fpsへ再圧縮し、3,351フレーム目（約1分51.7秒）で
1,649チャンク・524,288バイトを復元して全体CRC32と元BIOSの一致を確認しています。
解析中にブラウザをバックグラウンドへ移すと動画フレームのコールバックが間引かれるため、
完了までは受信ページを前面に置いてください。

一方、320×240・30fps・約127kbpsまで強く圧縮したH.264では1454/1649チャンクに
留まりました。低解像度・低ビットレートの組み合わせは避けてください。

## RCAコンポジット試験

`composite_test.cjs` はRGB画像を直接ぼかすのではなく、走査線ごとにYIQへ変換して
3.579545 MHzのNTSC色副搬送波へ直交変調し、コンポジット波形を復調してから受信側へ
渡します。基準値は [ITU-R BT.470](https://www.itu.int/rec/r-rec-bt.470/en) と
[TI SLOA040](https://www.ti.com/lit/an/sloa040/sloa040.pdf) を参照しています。

試験には色帯域制限、ノッチ/2ライン櫛形復調、色位相ずれ、ケーブルのゴースト、ノイズ、
走査線ジッタ、縦方向の混合、量子化、YUV 4:2:0を含みます。短いRCAケーブル、民生TV、
安価なUSBキャプチャ＋長いケーブルの3条件を通常テストで検査します。

```sh
node receiver/composite_test.cjs
node receiver/composite_test.cjs --full
```

`--full` は最も厳しい条件で512 KiB・1,649チャンクすべてを検査します。実行結果は
1,649/1,649チャンク、棄却0、全体CRC32一致、最小色距離55.6でした。通常テストには、
過剰な劣化でCRCエラーになる負の対照も含みます。

これは有効映像部分の信号経路モデルです。特定のPS1基板のビデオエンコーダー個体差、
同期信号やカラーバーストへのロック失敗、特定キャプチャ機器の240p誤判定までは再現しません。
その部分は実機試験で確認する必要があります。

## テスト

Node.jsがあれば、外部パッケージなしでプロトコル試験を実行できます。

```sh
node receiver/test.cjs
node receiver/camera_test.cjs
node receiver/composite_test.cjs
```

`camera_test.cjs` は30fpsカメラによる間引き、台形歪み、色かぶり、暗所、ノイズ、
ブロック量子化、フレーム落ちと次周回での回収を合成画像で検査します。
